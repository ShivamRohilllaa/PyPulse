Use cases

Where to look
when things slow down.

Follow an endpoint from its first SQL query to its next release.

Diagnose a Django endpoint ＋

Open Traffic and compare the SQL-per-request and p95 columns. When the same view grows from one query to twenty, inspect how it fetches related objects.

Compare two releases ＋

Run the same saved benchmark on staging before and after a change. Compare throughput, p95 and errors side by side, or download individual timings as CSV.

Catch a failing dependency ＋

Monitor an endpoint with an expected status and response text. Consecutive failed checks open an incident. A passing check records recovery. Publish selected monitors on a read-only status page.

Set a performance gate in CI ＋

Give the saved benchmark a p95 limit and an error-rate threshold. Queue it with a CI token, then read the final pass result before shipping.

Quick start

Connect your first API.

Start the dashboard, create a service token, then add the adapter to your app.

Start the workspace

From a terminal with Docker Compose installed:

git clone https://github.com/ShivamRohilllaa/PyPulse.git
cd PyPulse
docker compose up -d --build
docker compose exec web python manage.py createsuperuser

Sign in at localhost:8080, then choose Connect service.

Instrument your app

MIDDLEWARE = [
    "pypulse_agent.django.middleware",
    *MIDDLEWARE,
]

Install the agent into your app environment, set its URL and token, then add this line after your existing Django middleware definition.
